# ADR-0008: 运行时采样技术选型 PEP 669 `sys.monitoring`

- 状态：**已定案**（决策自 2026-08-21 生效；2026-10-03 追溯补记）
- 日期：2026-08-21（补记 2026-10-03）
- 决策者：产品负责人裁决（红线约束），开发团队实施并经 bench 实测定型
- 上游：`docs/python_ide_tech_plan_v3.md` v3.0（探针章节 · 开销红线 < 1.5x）
- 落地：`probe/src/pylume_probe/monitor.py`（采集核心）· `probe/tests/test_monitor.py` · `bench/`（开销基线）

## 背景

运行时智能的输入必须来自**真实执行**：函数参数、返回值、被访问的字段、抛出的异常。要拿到这些，就要在用户进程里挂钩子，而挂钩方式直接决定「用户能不能忍」。

硬约束：
1. **开销红线 < 1.5x**（类型采样口径）——探针跑在用户自己的脚本里，任何卡顿都是产品缺陷；
2. **零第三方依赖**（`probe/` 用 uv 管理，Python 3.13+）——不能给用户环境塞包，pip 安装即污染；
3. **不侵入**——不字节码重写、不 monkey patch 用户代码语义。

## 决策

1. **用 PEP 669 `sys.monitoring`（Python 3.12+）作为唯一挂钩原语**，不混用其他机制。
2. **事件策略（开销关键设计，三段式）**：
   - **发现窗口**：`PY_START` 全局事件发现"哪个函数在跑"，窗口内 `_in_window = True`；
   - **局部事件**：函数首次命中后 `set_local_events(code, PY_START | PY_RETURN)` 精细挂钩（`_armed` 集合记账），只对真正跑过的函数收事件；
   - **降采样 / 关窗**：窗口外只保留 `RAISE`（捕获异常类型标记），局部事件在收够样本后 `set_local_events(..., 0)` 解绑。
3. **tool id 动态探测**：`0-5` 逐个试，全被占用则抛 `RuntimeError`（实测语义记录于 `monitor.py` 头注，Python 3.13.7）。
4. **紧凑表示，绝不 repr 值本身**：类型以 `dict[str, int]` 紧凑字典 + shape 指纹落库；`shape` 列存**空串而非 NULL**（SQLite 唯一约束对 NULL 不生效，会导致 upsert 失效）。
5. **回调内极简**：实测确认（2026-08-21，3.13.7）`PY_START` 回调内 `sys._getframe(1)` 即被监控函数帧、`f_locals` 已含实参与默认值；**返回 `MISSING` 对全局事件无效（不能用于禁用），过滤只能在回调内快速 return**。

## 备选方案

| 方案 | 评估 | 结论 |
|---|---|---|
| `sys.settrace` / `sys.setprofile` | 全局回调每行/每函数触发，Python 层回调开销远高于 C 层事件；实测远超红线 | ❌ |
| 字节码插桩（改 `co_code`） | 采集最精细，但要重写用户函数字节码，极易破坏语义与 traceback，且不可跨版本 | ❌ 违反不侵入铁律 |
| `sys.monitoring` + 事件掩码（**选定**） | C 层事件分发、按需 arm 局部事件、窗口外近乎零成本；实测 1.35x < 1.5x | ✅ |
| 只靠静态分析（不采样） | 回到 PyCharm 那一档，且拿不到"真实跑过什么" | ❌ 放弃差异化 |
| py-spy 类外部采样器 | 只能给调用栈，不能给类型观测 | ❌ 不满足需求 |

## 后果

- **正面**：探针可随应用打包、零安装、零环境改动；真实运行数据成为 intel 的唯一输入源，形成别人抄不走的护城河。
- **负面 / 取舍**：
  - **"跑过"才有观测**——没跑过的代码运行时层是瞎的，这是特性不是缺陷（静态层兜底）；也正因如此，"从未运行"只能作为**死代码候选**而非结论（受采样与覆盖范围影响）。
  - 开销随被采样函数数增长，靠降采样与解绑压制；任何改采集路径的 PR 必须跑 bench 回归。
  - `sys.monitoring` 语义在 3.12/3.13 间有细节差异（事件掩码行为），升级 Python 版本须复测 `test_monitor`。
- **约束**：
  - `_active` 计数**禁止在 `PY_RAISE` 回调里递减**，只能在关窗决策点用 `_sync_active()` 从调用栈重算（否则抛异常路径上计数漂移）；
  - 改 `monitor` 必须跑 `test_monitor` 全量回归；
  - 轮询/落库设 `busy_timeout`，写库加 `WAL` + `synchronous=NORMAL`；
  - wheel 打包必须含顶层 `sitecustomize.py`；`argv[0]` 守卫用 `os.path.normcase` 归一；
  - 探针任何失败只打警告，**不改写用户进程退出码**。
