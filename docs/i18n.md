## 架构

```
shell/src/i18n/
├── index.ts             运行时：getLocale / setLocale / t / applyDomI18n / onLocaleChange
├── backendError.ts      后端错误翻译层（模板匹配 + 参数回填）
└── locales/
    ├── zh-CN/            按功能域拆分的中文真源（core.ts / git.ts / …）
    │   └── index.ts       聚合并导出 TKey（keyof typeof zhCN）
    └── en-US/            同名域文件；各域 Record<DomainKey, string> + 总表 Record<TKey,string>
```

- **扁平 key**（`menubar.file`）而非嵌套对象：`search.searchScope` 这类「既是叶子又是分支」的
  key 在嵌套结构里无法表达；扁平化后「漏译检查」退化为 key 集合运算。
- **DOM 标记**：`data-i18n`（文本）/ `-tip`（data-tip）/ `-aria`（aria-label）/ `-ph`（placeholder）/
  `-title`（title）/ `-alt`（alt）。`applyDomI18n()` 扫描并就地改写，写文本时只替换**直接子文本
  节点**，图标 `<i class="codicon">` 不会被抹掉。
- **语言存 `localStorage`**（键 `pylume.locale`），不进 `settings.json`：语言是本机壳偏好，
  与工作区无关；进 Settings 会牵动 Rust `Settings` 的三处同步义务（见 `state.ts` 相关注释）。
- **动态内容**由各域模块订阅 `onLocaleChange` 自行重绘：菜单在 `menuBar.ts`，Git 变更/分支面板在 `git.ts`，文件树按钮 tip/aria 与树占位在 `fileTree.ts`，运行组控件/历史列表/配置面板在 `runWidget.ts` / `runHistory.ts` / `runConfigPanel.ts`，环境状态栏 trigger 与面板在 `envPanel.ts`，依赖健康横幅/标签缓存/面板在 `depHealthPanel.ts`（`depHealth.ts` 侧仅刷新导出的 `NULL_DIST_WARNING`），调试工具栏/空态/Watches/Console 在三个调试模块中；运行时不持有模块渲染句柄，避免反向依赖。
- **调试模块初始化幂等**：语言切换只刷新已有 DOM 文案，不重复创建 Debug View/Console，不重复注册 DAP 监听，也不因切换语言发起新的变量或 Watches 求值请求。
- **复数**由 `Intl.PluralRules` 选择 `<key>.one` / `<key>.other`：调用点统一写 `t("git.discard.confirmMany", { count })`，不把英文语法散落到业务代码；语言包生成器会从含 `{count}` 的中文源条目展开两形。

## 新增文案：三步

1. **静态 HTML**：直接写中文，跑 `python3 tools/i18n/extract_html.py` 自动打 `data-i18n*` 标记并
   导出词条；再在 `tools/i18n/data/en_*.json` 补英文。
2. **TS 动态文案**：小型跨域文案在 `tools/i18n/data/manual_zh.json` 登记「key → 中文」，在同目录
   `en_*.json` 补英文；代码里写 `t("your.key")`。大型功能域先跑 `scan_ts.py` 生成清单，人工确认映射后
   用 `apply_ts.py` 改写源码，再用 `gen_domain.py --domain <域名>` 生成 `locales/zh-CN/<域名>.ts`
   与 `locales/en-US/<域名>.ts`。
3. 跑 `python3 tools/i18n/gen_locales.py`（核心/HTML）或 `python3 tools/i18n/gen_domain.py --domain <域名>`
   （功能域，如 `git` / `debug`）重新生成语言包；两者都会校验中英文 key 一一对应，gen_locales.py
   另校验分片合并时的**重复 key**（重复即失败——此前后者静默覆盖前者）。含 `{count}` 的域词条会展开复数变体。

然后 `npx tsc --noEmit` —— 英文漏了会直接编译报错。

### 生成器行为（重新生成前必读）

`gen_locales.py` / `gen_domain.py` 是**全量重写**，不是增量合并。两个后果：

1. **数据源没登记的 key 会被静默删除**。`locales/*/core.ts` 里存在于代码、但不在
   `html_dict.json` / `manual_zh.json` / `en_*.json` 中的键，重新生成后会消失（曾经因此丢过 27 个
   `settings.group.*` / `settings.kb.group.*` 等键）。**新增文案一律先登记数据源，再生成**；
   生成后 `git diff` 扫一眼有没有意外删除。
2. **生成器只输出 `// ---- <命名空间> ----` 段头，手写的行内注释会被抹掉**。`core.ts` 里的
   `// UI-31` / `// UI-32` 这类说明是生成后手工补的，每次重新生成都要再补一遍；若注释承载了
   不该丢的决策信息，请另记到文档而非语言包。
3. 键序由生成器**按字典序**排定，手工调整顺序无意义（下次生成即还原）。

## 新增语言

1. 建 `src/i18n/locales/<id>/`，复制 `zh-CN/` 与 `en-US/` 的域文件清单；每个域文件用
   `Record<DomainKey, string>` 对齐中文真源；
2. 建 `src/i18n/locales/<id>/index.ts` 聚合所有域，导出 `Record<TKey, string>`；
3. 在 `index.ts` 的 `Locale` 联合类型、`PACKS`、`LOCALE_OPTIONS` 三处登记；
4. 在 `index.html` 的语言下拉加一个 `<option>`。

## 后端错误

Rust 文案不动，前端按「中文模板 → 英文模板」匹配（`backendError.ts`）。Rust 侧改了错误文案而
映射表没跟上时，`python3 tools/i18n/scan_rust.py` 会报未登记条目（退出码 1）——建议接入 CI。
未命中模板时**原样返回中文**（宁可露原文，也不吞掉错误）。

## 后续（按优先级）

1. 新增文案按「新增文案：三步」随手纳管；每批抽完同步把「完整串断言」改成 `t(key)`
   （片段级 `toContain` 断言在默认中文下持续有效，强行转写需逐条复算插值参数、易错难维护）。
2. 英文文案带来的布局回归（英文普遍比中文长 30%~60%，按钮与侧栏宽度需过一轮视觉检查）。

## 踩坑清单（分批抽取积累，新增域 / 大批量改写前必读）

**转义与失真**（出现频率最高）

- 词条值必须存**运行时真实值**（裸反引号 / 单反斜杠 / 真实换行），源码级 `\`` 与 `\\` 经
  JSON→TS 链路会失真。典型：`fmt.sampleLine`、`rx.namedGroup` / `nonRawWarn` / `ctrlChar`、
  `git.branch.dirtyConfirm`（字面 `\n` 经 `textContent` 会显示成「\n」字样）。
- 含 `\n` 的文案（删除确认）不走映射表，由调用点拆成两条词条手工拼接。
- 含 ANSI 转义（`\x1b`）的终端文案不进词条：控制序列留在代码侧，仅提示文本经 `t()` 取词。
- 嵌套反引号模板（`` 共 ${count} 处匹配${truncated ? ...} ``）扫描器会错配闭合引号，
  整条手工拆成两条拼接；映射表只收规整模板。
- 中英两侧词条值必须都是运行时真实值，生成后人工比对一遍两侧产物。

**命名遮蔽**

- 源码里名为 `t` 的局部变量会遮蔽取词函数（`for (const t of app.tabs)`），
  tsc 报 `Type 'Tab' has no call signatures`；域内数据条目、`live-templates/builtin.ts` 的
  局部 helper 同理，改写前先改名（`tpl`）。
- 行区间脚本批量改名循环变量 `t` 会误伤区间内的 `t("…")` 调用，改名后须按 `t("域前缀` 反向修正；
  改名优先手工逐处或用更窄的词边界模式。

**语言切换时机**

- 模块级 `const` 词条常量与标签缓存对象会在语言切换后过期，改 `let` + `onLocaleChange` 重建
  （ES live binding 让导入方无需改动即可拿到新值）。
- 取词时机必须在渲染点；文案内嵌的模块级数组（`QUICKSTART` / `TOUR_ITEMS` / `SHORTCUTS`）与
  库码表（`STRFTIME_CODES` / `LOGGING_FIELDS` / `FORMAT_TYPES` / `FLAG_DEFS`）统一改
  「`buildXxx()` 构建函数 + `let` 缓存」并按元素存在性守卫重绘。
- 命令面板 label 与 registry 快照是注册时定格：语言切换时须重跑
  `registerQuickOpenActions(buildQuickOpenActions())` 与 `registry.rebuild(...)`
  （顺序：模块级重建 → 快照刷新 → 列表重绘，按注册顺序自然成立）。

**扫描器限制**

- 跨行模板字面量会被当「未闭合」整体跳过，其内短文案只以碎片出现在未命中清单——手工拆段取词，
  映射表只收单行模板。
- 注释里反引号包裹的中文会被扫描器当字符串命中，一律不进映射表（未命中清单里见到属预期）。
- `console.*` 日志按约定不纳管，大批量改写前先粗筛剔除。

**key 与覆盖**

- 域 key 必须自带域前缀写入映射表（`filetree.`）：`apply_ts.py` 对含 `.` 的 key 按跨域引用原样
  使用，两段式 key（如 `menu.xxx`）会被当成引用他域而非本域。
- 跨域同名 key 会被 `index.ts` 的 spread **静默覆盖**（tsc 不报错），靠 `i18n.test.ts` 全表扫描
  用例兜底，新增域时勿撞前缀。
- 分类既是「展示名」又是「排序恒定标识」：`manifest.category` / `PRESET_CATEGORIES` 继续存中文
  原文作标识，展示统一过 `types.ts::categoryLabel()`，第三方自定义分类原样透传。
- manifest 校验错误用结构化 `ManifestIssue{key, params}`（`ext.mf.*`），`manifest.ts` 保持零 i18n
  依赖，loader 层经 `t(e.key, e.params)` 转译。
- 设置搜索关键词表值为「英文词 + 中文检索词」混合串，英文侧只保留英文检索词。
- 复数机制副作用：含 `{count}` 的词条会被 `gen_domain` 自动展开 `.one` / `.other`，英文侧两个
  变体要各自写。
- `catch (e)` 的 unknown 实参改写后须包 `String(e)`（tsc TS2322 拦下）。
